## Contradictions And Cautions

- The objective is live and normative, while the affected Guide work pages are draft indexes. Proposal authors should write from the objective and implementation evidence, not imply these Guide pages are finished.
- Local runtime evidence is strong, but hosted acceptance is explicitly blocked by CAP-024. Any Guide language about deployment must separate local supervised-development readiness from hosted production readiness.
- The completion ledger warns against promoting broader package claims from focused verifier evidence alone. Claims should cite the exact service-workflow evidence or remain scoped.
- Direct read of `src/content/books/treeseed-guide.mdx` was denied by assignment scope. The injected book-core editorial note is usable, but the book record itself remains an access gap for this assignment.

## Terminology Decisions

- Use `workday`, not generic batch, job, or sprint, for supervised bounded execution windows.
- Use `planning` and `acting` as the mode terms; the implementation ledger says only `plan` and live execution modes exist and dry-run terminology was removed.
- Use `human authority` or `human review` for binding decisions; do not phrase agents as decision owners.
- Use `durable operational memory` for preserved reviewed output and provenance, not merely documentation.
- Use `local runtime verified` when citing the current capacity implementation evidence; reserve hosted or production claims until CAP-024 is resolved.

## Coverage Gaps

- Exact TreeSeed Guide book record could not be read within the scoped handle. Do not infer sidebar metadata beyond injected Guide work pages and book-core editorial note.
- Governance chapter pages, foundation pages, and knowledge publication pages were not in the shared context and were not queried further because the assignment scope centered on the work chapter and the query budget should stay economical.
- No scoped product UX implementation evidence was collected for the calm operational coordination interface described by `objective:core`; treat that as objective-level intent unless a later UI/source query verifies it.
- Existing Guide guarantee pages were listed by the work indexes, but individual guarantee bodies were not read. Proposal authors should read the exact guarantee page before quoting a specific guarantee promise.

## Affected Book Nodes

- `guide.work`: should frame work as the operational bridge from objective to supervised execution and durable memory.
- `guide.work.workdays`: should carry claims about scheduling, bounded duration/budget, eligible planning agents, approved-decision gates, summaries, and settlement, with local/hosted state separated.
- `guide.work.agents`: should carry claims about agent classes, planning/acting modes, TreeDX-scoped context/content access, execution traces, estimates, and recovery without weakening human authority.
- `guide.work.capacity-providers`: should carry claims about provider registration, availability, concurrency, reservations, usage settlement, recovery, and the hosted acceptance caveat.
